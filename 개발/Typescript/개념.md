``` typescript title="아래 코드에서 컴파일 에러가 나는 줄은 무엇이며 그 이유는?"
let a: number = 10;
let b: string = "10";

a = b;
```

A. <span style="filter: blur(5px);">
	a = b;
	- a는 number
	- b는 string
	- Typescript는 암묵적 변환을 허용하지 않음. (Javascript는 "10"을 10으로 착각하기 쉬움)
</span>

``` typescript title="아래 함수에서 return이 가능한 값은?"
function getStatus(flag: boolean): string | number {
	if (flag) {
		return "OK";
	}
	return 200;
}
```

Q.
	1. "OK"만 가능
	2. 200만 가능
	3. 둘 다 가능
	4. 컴파일 에러

A. <span style="filter: blur(5px);">
	3
	- 반환 타입이 string | number
	- 조건에 따라 서로 다른 타입 반환 가능
</span>

``` typescript title="아래 코드 중 에러가 발생하는 것은?"
interface User {
	id: number;
	name: string;
}

const u1: User = { id: 1, name="Tom" };
const u2: User = { id: 2 };
const u3: User = { id: 3, name="Jane", age: 20 };
```

A. <span style="filter: blur(5px);">
	u2, u3
	- u2 : name 누락
	- u3 : age 정의되지 않은 속성
	- Typescript는 정확한 구조를 요구
</span>

``` typescript title="아래 변수 x의 타입은?"
let x = [1, 2, 3];
```

Q.
	1. number
	2. number[]
	3. any[]
	4. (number | string)[]

A. <span style="filter: blur(5px);">
	2
	- Typescript는 강력한 타입 추론
</span>

``` typescript title="이 코드가 동작되도록 올바르게 개선될 수 있는 방법은?"
let name: string = null;
```

A. <span style="filter: blur(5px);">
	string 타입에서는 null 불가
	- let name: string | null = null;
</span>

``` typescript title="컴파일 에러가 나는 줄은? (보기에서 선택)"
let a: any;
let u: unknown;

a.toUpperCase();
u.toUpperCase();
```

Q.
	1. 없음
	2. a.toUpperCase();
	3. u.toUpperCase();
	4. 둘 다

A. <span style="filter: blur(5px);">
	- any : 검사 포기
	- unknown : 확인 후 사용 강제
</span>
