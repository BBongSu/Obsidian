### 단점

1. 데이터베이스(DB) 인덱스 효율 저하
	- 문제: 목록을 불러올 때마다 WHERE parent_id IS NULL 또는 is_latest = TRUE 같은 필터링 조건을 매번 걸어야 함.
	- 리스크: 데이터가 수만 건 이상 쌓이게 되면, 숨겨진(반려된) 문서들까지 모두 인덱스 범위에 포함되어 조회 성능이 점차 떨어질 수 있음. (반려가 잦은 조직일수록 기하급수적으로 늘어남)

2. 통계 및 대시보드 왜곡
	- 문제: 관리자 페이지에서 "전체 결재 건수"를 집계할 때 주의.
	- 리스크: 단순 COUNT를 하면 숨겨진 문서까지 포함되어 실제 업무량보다 훨씬 많은 수치가 집계됨.

3. 파일 서버 용량 낭비 (지출결의서)
	- 문제: 문서를 복제할 때 첨부파일 정보도 같이 복제.
	- 리스크: 사용자가 용량이 큰 파일을 올리고 5번 반려 당했다면, 실제로 서버에는 똑같은 파일 5개가 생성.

4. 추후 조상 찾기 복잡
	- 문제: 3차 재기안된 문서에서 1차 반려 당시의 문서를 찾아야 할 때.
