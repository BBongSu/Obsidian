Q1. Map이랑 DB 컬럼 매칭할 때 맨날 이렇게 노가다 해야돼?
A1. SQL에서 직접 코드 뽑아내자.

``` sql title="예시"
SELECT CONCAT('map.put("', column_name, '", StringUtil.isNull(map.get("', column_name, '"),""));')

FROM information_schema.columns

WHERE table_name = 'bpp_acc_evidtax';
```

3. 개발하는데 시간이 오래 걸리는 이유가 뭘까?

A1. 수많은 이유 중 하나를 자세히 생각해봤는데 단어 하나에 많은 경우의 수가 발생하기 때문이다.

>상황

- 나는 개발자, 상사는 PM, 이사님은 클라이언트(고객)다.
- 이사님은 자기 회사에 판매하는 제품에 대한 결제 시스템이 없다.
- 인터넷이나 휴대폰으로 결제 할 수 있게 개발이 필요하다.

>대화

- **이사님** : "결제 시스템 만들어줘"
- **상사** : "ㅇㅋ"
 
- ... (결제 개발에 앞서 설계중) ...

- **상사** : "제품에 대한 가격은 공급가액 + 부가세 + 봉사료를 합해서 나오는 총액이다. 이 중에 봉사료는 0원으로 고정하자."

- **나** : **"네"** or **"진짜 그래도 돼요?"**
- **나** : (생각중) "네"인 경우, 봉사료는 0원으로 고정하면 되겠다.
- **나** : (생각중) "진짜 그래도 돼요"인 경우, 잠깐만 이 회사는 제품을 팔면서 봉사료가 한번도 발생을 안한다고 장담을 못하겠는데.. 만약 발생하면?
- **나** : 봉사료가 흔하게 발생하진 않는데.. 혹시 모르니 대비 해놓을까요?

- **상사** : **"그러던지. 알아서해"** or **"안 발생해. 걱정하지마"** or **"발생하는 일은 드물어. 그때가서 처리해"**

- **나** : (생각중) 1번째인 경우, 그럼 나중에 봉사료 입력할 수 있게 개발
- **나** : (생각중) 2번째인 경우, 이 회사만 쓸거 아닌데 대비 해놓자는 의견을 제시해보자
- **나** : (생각중) 3번째인 경우, 봉사료 발생할 때마다 개발자 DB에서 수기로 수정

- **나** : (생각중) ... 아!

- **나** : (3번째) 봉사료 발생할 때마다 제가 DB로 수정하긴 귀찮아서요.
- **나** : (2번째) 이 회사만 쓸거 아니니까 발생하면
- **나** : (1번째) 나중에 봉사료 입력할 수 있게 해놓죠.

- **상사** : 그래

>정리

- 최소한 내가 고생하지 않겠다는 범주 내에서 계획 필요
