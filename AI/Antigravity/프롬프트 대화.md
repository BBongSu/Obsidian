### 분석하기 위해 해야될 것

- 프로젝트 개요, 주요 패키지 구조, 핵심 도메인 및 엔티티 관계, 공통 모듈 위치 작성
- AI가 코드를 추적해 들어갈 수 있는 경로를 지정
- 불필요한 디렉토리 제어, 대용량 파일/자동 생성 파일 제외
- 도메인 용어집 제공
- 분석 과정에서 불확실한 부분을 먼저 되묻게 만들기

### 설계하기 위해 해야될 것

- 코드는 아직 작성하지 말고, 아래 항목을 포함한 구현계획서를 먼저 작성
	- 수정/신규 생성할 파일 목록 및 각 파일의 역할
	- 메서드 시그니처 및 DTO 구조 (Request/Response)
	- 예외 처리 시나리오 (어떤 상황에서 어떤 Custom Exception을 던질 것인지)
	- 트랜잭션 범위 및 데이터 변경흐름

### 코드 구현하기 위해 해야될 것

- 현재 구현된 소스 패턴을 크게 벗어나지 않고 아래 사항 숙지
	- 불필요한 코드 사용 금지
	- 변경 가능성이 없는 필드는 final 및 생성자 주입 활용
	- Java 17 문법 적극 활용

### 테스트하기 위해 해야될 것

- 방금 작성한 파일에 대한 JUnit5 + AssertJ 기반 단위 테스트 코드 작성
	- 정상 흐름 테스트
	- 경계 조건 및 예외 흐름
	- Mockito를 활용하여 DB 의존성 없이 Service 로직만 격리 검증

### 리뷰하기 위해 해야될 것

- 지금까지 작성한 전체 코드 검토. 아래 항목에 해당되는 문제가 있는 확인 및 개선할 점이 있다면 리팩토링된 코드를 제안
	- N+1 문제나 동시성 이슈가 생길 여지가 있는지?
	- 가상 스레드 환경에서 Blocking이 심하게 일어나는 지점이 있는지?
	- 예외 처리가 누락되었거나 로그가 불충분한 곳이 있는지?
