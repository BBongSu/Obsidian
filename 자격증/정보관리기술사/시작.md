	- 경력 뿐만이 아닌 현재 갖고있는 직업인 개발자 그 이상의 능력을 올려야만 안정적인 삶을 영위할 수 있다고 판단
	
	- "국내 IT 최고 자격증이라서?", "딴다고 의미가 있을까?", "수석감리원 하려고 이걸 딴다?", "대기업의 인맥을 쌓고 스폰도 잘 들어와서 딴다?", "강의 하려고 이걸 딴다?" 고작 이런 용도로만 가려고 한다면 시작도 안했다.

## 🏌️ 시작

- 먼저 기출문제와 답지를 봤다.
- 논술형이다.. 벌써 막막해졌다. 스트레스 안 받고 시작하려면 작게 진입하라고 한다.

- 문제에 WBS 작성 방법이 나왔다
- 구글링을 해본다
- 최소 1줄 ~ 최대 3줄까지 요약해본다.
	- WBS가 뭐지?
		- 프로젝트를 진행할 때 만들어야 할 최종 결과물의 업무 단위들을 세분화하여 적어놓은 시각적 도구
	- 이걸 왜 써?
		- **업무 분담** - 프로젝트를 진행할 때 누구한테 시킬건지 넘겨줄 수 있음
		- 범위 통제 - 클라이언트가 기능 추가를 요청할 때 WBS에 없던 내용이라고 방어 가능
		- 일정 및 비용관리 - 일 단위로 쪼개서 "이 기능 만드는데 얼마나 걸리고 돈 얼마 든다." 답이 나옴
	- 안 쓰면 어떻게 돼?
		- 프로젝트를 진행할 때 업무 분담을 어떻게 할건지 난관이 생김
		- 클라이언트가 기능 추가를 요청할 때 방지가 안됨
		- 프로젝트 기간이 1년으로 잡혔는데 오늘 내일 뭐할건지 계획이 없음
	- 어떻게 작성해?
		- 1단계 : 최종 인도물 식별
			- 먼저 프로젝트 결과물이 무엇인지 명확히 정의 ex) 쇼핑몰 시스템 구축
		- 2단계 : 하향식 분할
			- 상위 단계에서 하위 단계로 대분류,중분류,소분류 순으로 일을 쪼갬 ex) 회원 관리 → 회원 가입 → 본인 인증 기능
		- 3단계 : **워크 패키지** 정의
			- 더 이상 쪼갤 필요가 없는 최하위 작업 단위를 결정 ex) 8/80 법칙 (8시간에서 80시간 안에 끝낼 수 있는 분량)
		- 4단계 : 계정 코드 부여 및 사전 작성
			- 각 작업에 추적 가능한 ID를 ex) 1.1, 1.1.1 부여하고, 각 작업의 담당자, 기간, 검수 조건 등을 적은 상세 명세서(WBS 사전)을 만듦
	- 핵심 키워드가 뭐야?
		- **100% 원칙**
			- 상위 항목의 자식 항목들을 모두 합치면 정확히 부모 항목의 100% 되어야 하는 원칙 (작업의 누락과 중복이 없어야 함)
		- 워크 패키지
			- WBS의 최하위 단위
		- WBS 사전
			- 그림만으로는 알 수 없는 작업의 상세 내용을 글로 풀어쓴 문서
		- 계정 코드
			- 각 작업 항목에 부여된 고유 숫자(식별자)
